# 0.3.0 — 2026-10-17

## Changed

- **Observation bounds** now use the earliest/latest fetched dates before preview slicing; `observation_start` and `observation_end` are nullable for successful empty batch entries ([#21](https://github.com/cyanheads/federal-reserve-mcp-server/issues/21)).
- **`canvas_id`** is removed from observation input and rejected; each spill creates a fresh dataframe ([#17](https://github.com/cyanheads/federal-reserve-mcp-server/issues/17)).
- **Dataframe SQL** rejects engine-setting functions such as the formerly accepted `current_schema()`, alongside dynamic table lookup; query staged dataframes directly.
- **Spill guidance** reaches both response surfaces with the real preview count and executable describe/query calls ([#19](https://github.com/cyanheads/federal-reserve-mcp-server/issues/19)).
- **Final totals** have contract coverage across search, release lookup, and dataframe queries; dataframe count descriptions reflect provider and row-limit semantics ([#22](https://github.com/cyanheads/federal-reserve-mcp-server/issues/22)).
- **Development guidance** and validation scripts are synchronized with the adopted framework.

## Fixed

- **Observation dates** reject impossible calendar dates before requesting FRED, preserving blank optional dates as unset ([#10](https://github.com/cyanheads/federal-reserve-mcp-server/issues/10)).
- **Search filters** require a complete pair with a nonblank value and return `invalid_filter` before fetching ([#18](https://github.com/cyanheads/federal-reserve-mcp-server/issues/18)).
- **Release schedules** request the nearest five dates on or after today in UTC, including scheduled dates without data ([#20](https://github.com/cyanheads/federal-reserve-mcp-server/issues/20)).
