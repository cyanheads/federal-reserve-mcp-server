# 0.1.4 — 2026-05-23

## Fixed

- **`fred-service.ts`** — API key was included in `data.url` on HTTP error responses; `sanitizedUrl` now strips the `api_key` query param before attaching to error data.
- **`fred-get-series.tool.ts`** — single-ID failure now throws `series_not_found` instead of `partial_failure` with a silent success path. All-failed multi-ID path now includes `failed` array in error data.
- **`fred-get-observations.tool.ts`** — `observation_count` on inline-capped results now reflects the truncated array length, not the pre-cap upstream count. Single-series upstream failures surface as `series_not_found` with a recovery hint rather than falling through to the multi-series `failed` accumulator.
- **`fred-search-series.tool.ts`** — zero-result response now echoes the query and active filters with a concrete recovery suggestion. `query` and `active_filters` added to output schema and surfaced in `format()`.
- **`fred-get-release.tool.ts`** — `search_alternatives` moved into the error message body so it surfaces in `content[]` on `ambiguous_release_search`; previously only present in `data`.
- Tool descriptions: implementation detail leaks removed (`fred-get-series`, `fred-get-observations`, `fred-get-release`, fileoverview comments).

## Security

- **API key leak** — FRED API key was appended to error response `data.url` on HTTP failures. Fixed by stripping `api_key` from the error URL; the upstream request still uses the full URL.
