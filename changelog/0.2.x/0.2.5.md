# 0.2.5 — 2026-10-03

## Changed

- **Error handling** uses the framework's declared recovery fill in place of redundant forwards; error responses now include request IDs for log correlation, and client log notifications honor level filtering.
- **Framework runtime** adopts JSON storage round-tripping, context-free error data, input repairs, and DuckDB scratch/error handling from the 0.13.7–0.13.11 upgrade.
- **Docker builds** cross-install production dependencies on the build platform, install OpenTelemetry peers at the framework's declared ranges, and remove unused musl bindings.
- **Development tooling** synchronizes framework skills and scripts, adds packaging and tag checks, separates CodeQL language categories, and broadens environment/token exclusions; README and configuration guidance follow the installed runtime.

## Fixed

- **DataCanvas** includes the DuckDB production dependency for npm and Docker installations, with real-provider regression coverage for observation staging, describe, SELECT, and drop ([#26](https://github.com/cyanheads/federal-reserve-mcp-server/issues/26)). Portable `.mcpb` bundles omit native bindings; use npm or Docker for canvas mode.
- **`fedreserve_get_observations`** treats blank optional `observation_start` and `observation_end` values from form clients as unset, without forwarding them to FRED.
- **MCP Registry launch metadata** uses `npx` without ignored script arguments and explicitly selects HTTP for its Streamable HTTP entry.
